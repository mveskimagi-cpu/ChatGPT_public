# OpenAI credit exhaustion and repeated Quant reviews

## Evidence and impact

The first failed run in the incident window is [37508990466](https://github.com/mveskimagi-cpu/ChatGPT_public/actions/runs/37508990466). At 2026-10-06 18:09:06 UTC (21:09 Tallinn), the Critic call returned HTTP 429, `type=insufficient_quota`, `code=credit_balance_exhausted`, and reported no remaining API credits. Subsequent sampled runs, including [37565300085](https://github.com/mveskimagi-cpu/ChatGPT_public/actions/runs/37565300085), failed at the first Quant/Macro call with the same response. This is billing exhaustion, not a transient requests-per-minute limit.

The last completed review was 2026-10-06 17:56 UTC. The ledger contains 43 completed team reviews, including 28 repeated MSTR reviews between 04:29 and 13:09 UTC before the US regular session, all with the same trigger key. The queried history through 2026-10-07 03:07 UTC contained 33 consecutive failed scheduled runs. No claim is made about the exact monetary cost: historical token usage/billing was not recorded by the consumer. Cash, trades and quantities still reconcile. The last committed trades before the incident were HPE BUY EUR100 and SHOP BUY EUR100; failed later proposals were not committed as trades.

## Causes

1. The API account/project ran out of credits. Only its owner can restore billing capacity.
2. The decision gate unconditionally called the model whenever a position target/invalidation level remained crossed. This branch preceded the duplicate, movement and time gates, and no freshness check existed before model calls.
3. New positions copied a watchlist entry trigger into their `target` text. The sensor interpreted an already-satisfied entry level as an exit-target alert on every run.
4. Repeated full reports expanded `data.js` to about 1.34 MB, beyond the GitHub Contents API inline-content threshold: the normal file-read tool returned empty content. Git blob reads recovered the exact source. Full reports are now archived individually under `quant/agent-reviews`, with compact summaries (latest 200), cumulative counts and archive links in the ledger. Archives are audit evidence, never an alternative portfolio.
5. Quota failure had no durable retry circuit. Every scheduled trigger tried the exhausted API again and failed the GitHub job. Decision-time market marks were also lost on the exception.

These defects affected the initial multi-role integration. A successful initial HOLD run did not cover repeated closed-market execution or later quota exhaustion.

## Repair

- Require fresh triggered-symbol quotes before invoking any model. Preserve new invalidation and material-move review paths; apply the existing 60/240-minute review intervals to repeated levels.
- Suppress legacy entry-as-target text when it matches the structured entry rule; retain real explicit target rules and original historical records.
- Persist `BLOCKED_QUOTA` under `automationHealth.openai` in the authoritative `data.js`, with error code/role, first/latest failure, next eligible probe and source run for incident initialization. No API key or secret is stored.
- On known quota failure, preserve trades, cash, quantities, lastTrade, last successful agent reports and trigger-processing state. Persist only validated market marks and provider health through the existing atomic commit/read-back path. Do not label the block HOLD.
- Retry no more often than every six hours, and only with an otherwise eligible fresh signal. After top-up the existing workflow's manual `retry_openai` input permits an earlier attempt without bypassing any trading guard. A fully completed team clears the block.
- Show the blocked state and historical nature of prior reports on the dashboard and Actions summary. Keep unknown/transient API and ledger failures visible as failures.
- Count successful requests and provider-returned input/output/cache tokens prospectively.

## Verification and recovery boundary

The test suite includes production-ledger reconciliation, repeated/stale-target suppression, immediate new invalidation, quota classification, delayed probe, partial-team failure and a consumer-level pause/retry/recovery test proving no fabricated trade, HOLD or processed-trigger receipt. The suite passed locally before deployment, including full-review archival and compact-summary integrity.

The production health record is initialized from the observed GitHub error, not from an invented new API call. A successful post-fix Actions run can verify the monitoring path and absence of repeated billed calls while credits are exhausted. It cannot establish that paid AI decisions have resumed. That requires adding credits in the OpenAI organization/project used by the repository's existing API secret, then a successful full team review. Do not change credentials or billing settings as part of this fix.
